## 三、发现的问题与修复

### 问题 1：MR 导出因 dept_id 为 NULL 崩溃

现象：`POST /api/mapreduce/export` 返回 500，`Cannot invoke "Integer.intValue()" because "getDeptId()" is null`。

原因：业务库存在遗留测试数据（id=68 `Test99`）dept_id 为 NULL，导出时直接拆箱导致 NPE，整批导出中断。

修复：`MrInputExporter` 新增 `deptIdOf()` 兜底方法，null 映射为 0（未分配部门），保证单条脏数据不会中断整条链路。

### 问题 2：端口被环境变量覆盖，Tomcat 起在随机端口

现象：日志出现 `Tomcat initialized with port 0`，实际监听 64785 等随机端口，配置文件里明明写了 9090。

原因：环境中存在 `SERVER__PORT=0` 变量，Spring Boot 的宽松绑定将其解析为 `server.port`，优先级高于 YAML 配置。

验证：临时诊断类读取 Environment，确认 `server.port=0` 而 prod 文档其他配置正常。

处置：启动前 `unset SERVER__PORT`，或在启动参数中显式指定 `--server.port=9090`（注意该参数是程序参数，必须写在主类名之后）。

说明：这是环境问题而非项目缺陷，在 VSCode / Eclipse / 正常终端中启动不受影响。

### 问题 3：DQC 把请假记录误判为脏数据

现象：Job1 输出 MISSING_SIGN_IN=6,346（5.4%），远高于生成器 0.3% 的注入比例。

原因：请假、病假、年假、调休、旷工当天本来就没有打卡记录，属正常业务，却被统一计为数据缺失。

修复：`DeptEfficiencyJob` 增加判断——只有 `leave_type='正常'` 且签到为空才计入 `MISSING_SIGN_IN`；请假类单独计入新计数器 `LEAVE_NO_SIGNIN`。

修复后实测：MISSING_SIGN_IN=168（真异常，与 0.15% 注入率吻合），LEAVE_NO_SIGNIN=6,136（业务正常）。

### 问题 4：缺 hive-service 依赖，mode=real 时连接必失败

现象：`/api/hive/status` 报 `org/apache/hive/service/cli/HiveSQLException`（NoClassDefFoundError，只有一个类名，极难排查）。

原因：pom 中 `hive-jdbc` 排除了 `hive-service`（为避免引入 jetty/tomcat 冲突），而 HiveConnection 建立连接时必须加载该类。

修复：新增独立的 `hive-service` 依赖，版本由 `${hive.version}` 统一管理（3.1.3），并排除其全部传递依赖，只补齐运行时类，不引入额外冲突。

### 问题 5：模拟模式下 Hive 接口抛 500

现象：`/api/hive/tables`、`/schema/init` 等在 simulator 模式下直接 500，前端拿到的是异常堆栈而非可读提示。

修复：`HiveController` 新增 `requireRealMode()` 前置校验，非 real 模式直接返回中文提示（告知需先 `docker-compose up -d` 并切换 `bigdata.mode=real`），同时对各接口补 try-catch 兜底。

### 3. MyBatis Plus 分页方言 —— 已修复（2026-10-05）

**问题**：`MyBatisPlusConfig` 中分页插件写死 `DbType.H2`，而 prod 使用 MySQL。经源码与实测验证，**当前不产生任何功能问题**，原因如下：

1. MyBatis Plus 3.5.7 的方言实现类中**没有 `H2Dialect`**，且 `DbType.H2.mysqlSameType()` 返回 false
2. `DialectFactory.getDialect(DbType.H2)` 最终落到 `PostgreDialect`，生成 `LIMIT ? OFFSET ?`
3. MySQL 同样支持 `LIMIT row_count OFFSET offset` 语法，且 MP 绑定参数顺序为 (limit, offset)，语义等价

实测对照（`GET /api/employee/page?page=N&size=5`，注意参数名是 `page` 不是 `current`）：

| 页码 | 接口返回 id | 数据库 `LIMIT 5 OFFSET ?` |
|---|---|---|
| 1 | 1~5 | 1~5 |
| 2 | 6~10 | 6~10 |
| 3 | 11~15 | 11~15 |
| 50 | 252~256 | 252~256 |

结论：total、pages、偏移量全部正确，属于「歪打正着」而非缺陷。

**修复**：改为按数据源驱动动态选择方言，而非按 profile 名称判断（驱动类名与实际数据库强绑定，profile 名称可被随意修改）：

```java
@Value("${spring.datasource.driver-class-name:}")
private String driverClassName;

@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
    interceptor.addInnerInterceptor(new PaginationInnerInterceptor(resolveDbType()));
    return interceptor;
}
```

`resolveDbType()` 识别 mysql / mariadb / h2 / postgresql / oracle / sqlserver，未识别时返回 null，交由 MyBatis Plus 从 JDBC 连接元数据自动推断，避免在陌生环境下直接报错。

**修复后验证**（开启 MySQL general log 抓取应用实际发出的 SQL）：

```sql
SELECT e.*, d.name as dept_name FROM employee e
LEFT JOIN department d ON e.dept_id = d.id ORDER BY id ASC LIMIT 10,5
```

`LIMIT 10,5` 为 MySQL 方言写法，修复前为 `LIMIT 5 OFFSET 10`（PostgreSQL 写法），方言已正确切换。分页功能同步复测：page=3 size=5 返回 id 11~15，与 SQL 直查一致。

## 八、页面切换加速（静态资源本地化）

### 1. 定位过程

用户反馈「可视化页面之间切换等待太久」。先分别测量后端与前端，避免盲目优化：

| 对象 | 实测 |
| --- | --- |
| `/api/efficiency/*` 8 个接口 | 最慢 top-employee 0.315s，其余 0.004~0.23s |
| `/api/bigdata/status`、`/api/analysis/*`、`/api/employee/page?size=9999` | 0.003~0.022s |
| `/efficiency` 页面 HTML | 0.005s |
| **CDN `echarts.min.js`** | **TTFB 1.585s** |
| **CDN `jquery.min.js`** | **TTFB 0.814s** |
| CDN `bootstrap-icons.min.css` | TTFB 0.085s |
| CDN `bootstrap.min.css` | TTFB 0.073s |

结论：瓶颈 100% 在**外网 CDN**，后端接口全在毫秒级，无需改 SQL。

### 2. 修改内容

1. 把 6 个静态资源下载到 `src/main/resources/static/vendor/`：
   `echarts.min.js`（1.0MB）、`jquery.min.js`、`bootstrap.min.css`、`bootstrap.bundle.min.js`、`bootstrap-icons.min.css`、`fonts/bootstrap-icons.woff2|woff`（字体跟着 CSS 的相对路径 `fonts/` 放）。
2. 12 个模板共 **34 处** CDN 链接批量替换为 `/vendor/xxx`，全库零外链残留。
3. `application.yml` 新增静态资源缓存：`spring.web.resources.cache.cachecontrol.max-age=604800`（7 天）+ `cache-public`，浏览器切换页面直接走本地缓存。
4. 开启 gzip：`server.compression.enabled=true`、`min-response-size=1024`，echarts 1MB 压缩后约 300KB。

### 3. 优化后实测

| 资源 | 优化前 | 优化后 |
| --- | --- | --- |
| echarts.min.js | 1.585s（外网） | **0.005s**（本地 + 缓存） |
| jquery.min.js | 0.814s | 0.024s |
| bootstrap.min.css | 0.073s | 0.005s |
| bootstrap-icons.min.css | 0.085s | 0.005s |

响应头确认：`Cache-Control: max-age=604800, public`、`Content-Encoding: gzip` 均已生效；8 个页面全部 200；字体 `/vendor/fonts/bootstrap-icons.woff2` 200。

### 4. 踩坑

`server.compression.mime-types` 自定义时只写了 `application/javascript`，而 Spring Boot 实际返回的 Content-Type 是 `text/javascript`，导致 gzip 静默不生效。**去掉 mime-types 配置用默认值即可**（默认已含 text/javascript、text/css、application/json）。

### 5. 约定

新增页面一律引用 `/vendor/` 下的本地资源，不要再引 CDN——断网或 CDN 抖动时页面会直接白屏，答辩演示风险大。
